title: Connect AI apps

xstate runs an MCP server, so the AI app you already use can read your mail, write drafts, check your calendar
and search your files. You choose what each app may do when you connect it, and you can disconnect it at any time.

The address to give your app:

```
https://mcp.xstate.com/mcp
```

## Connect your app

Every app sends you to xstate to sign in and approve it the first time it connects. See
[What you approve](#what-you-approve).

### Claude

In Claude (web or desktop), open **Customize → Connectors**, choose **Add → Add custom connector**, enter `xstate` as
the name and the address above, then click **Add** and **Connect**.

On a Team or Enterprise plan, an Owner adds the connector under **Organization settings → Connectors** first. Each
member then connects it with their own xstate account.

### Claude Code

```bash
claude mcp add --transport http xstate https://mcp.xstate.com/mcp
```

Then run `/mcp` in Claude Code, pick xstate and sign in. Or sign in from your terminal with
`claude mcp login xstate`.

### Codex

```bash
codex mcp add xstate --url https://mcp.xstate.com/mcp
codex mcp login xstate
```

The second command opens xstate in your browser.

### Cursor

Add this to `~/.cursor/mcp.json` (or `.cursor/mcp.json` in one project):

```json
{
  "mcpServers": {
    "xstate": { "url": "https://mcp.xstate.com/mcp" }
  }
}
```

Then open **Cursor Settings → MCP** and click **Connect** next to xstate.

### ChatGPT

ChatGPT calls these apps or connectors, and where you add one depends on your plan and the current ChatGPT
settings. Look for creating an app or connector from a server URL (some plans need **Developer mode** turned on
first), and enter the address above with OAuth sign-in.

### Other apps

Any app that supports remote MCP servers over Streamable HTTP with OAuth can connect. See
[For developers](#for-developers).

## What you approve

When an app connects, xstate shows you:

- **Which app is asking.** Apps that publish their details on their own domain (Claude, ChatGPT and Cursor do) show
  that domain. Others show only the name they gave, marked as unverified.
- **Where access will be sent,** and a warning when that is a program on your own computer. Continue only if you
  just started connecting from it.

Then you choose:

| Choice | Options | Starts on |
| - | - | - |
| Organization | Any you belong to | The first |
| Mailboxes | Mailboxes you can read | Your own mailbox |
| Email | Read only · Draft only · Draft and send | Draft only |
| Calendar, Storage, Contacts | Off · Read · Read and change | Read |
| Manage domains and mailboxes | Off or on, for owners and admins | Off |

With **Draft only**, the app writes drafts and you send them. It can never send mail unless you choose
**Draft and send**.

An app never gets more than you have: every action is checked against your own access, then narrowed to what you
chose. Mail and calendars of mailboxes you didn't pick are out of reach, including through search.

Some things are never available to a connected app: resetting passwords, giving people access to mailboxes, API
keys, AI provider keys, secrets, inviting or removing members, and public file links.

## Manage connected apps

**Settings → Connected apps** lists the apps you connected, what each may do and when it was last active, with
**Disconnect**. Owners and admins also see every app connected to the organization and can disconnect any of them.
Access ends at once.

A connection ends by itself 30 days after it was last used. To change what an app may do, connect it again: the
new choices replace the old ones. Each app can make up to 120 calls a minute.

Email, files and calendar invitations are written by other people. A message can try to talk an AI app into doing
something you didn't ask for. xstate tells connected apps to treat what they read as information, not
instructions, but keep an eye on what your app does, and give it no more than it needs.

## For developers

- **Transport:** Streamable HTTP at `https://mcp.xstate.com/mcp`. Stateless: no session is kept between requests.
- **Sign-in:** OAuth 2.1 with PKCE (S256). xstate is its own authorization server. Discovery follows the MCP
  authorization spec: a request without a token gets `401` pointing to
  `/.well-known/oauth-protected-resource/mcp`, which names the authorization server, whose metadata is at
  `/.well-known/oauth-authorization-server`.
- **Client registration:** Client ID Metadata Documents (preferred) or Dynamic Client Registration at
  `/oauth/register`.
- **Scopes:** request none. The person picks them on the consent page, and the token carries what they chose.
- **Tokens:** access tokens last one hour; refresh tokens rotate on use, and a connection ends 30 days after its
  last refresh.
- **Errors:** a tool that fails returns `isError` with `{ "error": { "code", "message" } }`, the same codes as the
  HTTP API. Over the rate limit the code is `rate_limited`.
